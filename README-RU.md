# Neovim для C#/.NET

Профиль создан отдельно от основной конфигурации AstroNvim.

## Версионирование конфигурации

Эта папка является отдельным локальным Git-репозиторием:

```text
C:\Users\ThinkPad\AppData\Local\nvim-csharp
```

Посмотреть состояние:

```bash
git -C /c/Users/ThinkPad/AppData/Local/nvim-csharp status
```

Посмотреть историю изменений:

```bash
git -C /c/Users/ThinkPad/AppData/Local/nvim-csharp log --oneline --decorate
```

После изменения конфигурации:

```bash
cd /c/Users/ThinkPad/AppData/Local/nvim-csharp
git diff
git add init.lua lua/config.lua lua/hints.lua lua/plugins/init.lua README-RU.md lazy-lock.json
git commit -m "config: update nvim-csharp profile"
```

Перед коммитом проверяйте `git status`, чтобы случайно не добавить временные
файлы. Правила исключений находятся в `.gitignore`.

Основная конфигурация AstroNvim не входит в этот репозиторий.

## Запуск

Перейдите в каталог решения и откройте его как папку:

```text
cmd / PowerShell:   vimsharp .
Git Bash:           vimsharp.cmd .
```

Откроется дерево файлов на весь экран. Выберите `.cs`-файл и нажмите Enter.
Когда Roslyn подключится, внизу появится сообщение «Roslyn подключён».

`vimsharp` сам выставляет `PATH` и `NVIM_APPNAME`, вручную ничего задавать не нужно.
В Git Bash пишите `.cmd` и пути через `/`: `vimsharp.cmd ./AsyncDebugLab.sln`.

## Главное правило

Забыли клавишу? Нажмите пробел и подождите: появится меню подсказок.
Поиск по всем клавишам: `пробел f k`. В дереве файлов справка открывается по `?`.

## Памятка

```text

Esc             закрыть всплывающее окно / снять подсветку поиска
Ctrl+o          назад после перехода (gd, gr)

ФАЙЛЫ
<leader>e       дерево открыть/закрыть (сразу показывает текущий файл)
  Enter         открыть          v / s   открыть справа / снизу
  a / r / d     создать / переименовать / удалить       q  закрыть дерево
<leader>ff      найти файл       <leader>fg  найти текст
<leader>fb      открытые файлы   <leader>fk  найти клавишу

КОД
gd / gr / K     определение / ссылки / документация
<leader>lr      переименовать    <leader>la  исправления (code action)
<leader>lf      форматировать    <leader>ld  ошибка в строке
]d / [d         следующая / предыдущая ошибка

ЗАПУСК
<leader>rr      запустить проект
<leader>rt      тесты
<leader>rs      всё меню .NET (build, restore, выбор проекта)

ОТЛАДКА
<leader>db      breakpoint       <leader>dc  старт / продолжить
<leader>dm      включить Debug Mode: панель поверх левой колонки Neo-tree и клавиши o/i/u/c
<leader>do/di/du  шаг через / внутрь / наружу
<leader>dx      остановить       <leader>dd  окна отладки показать/скрыть
<leader>dr      REPL             <leader>de  вернуться в код

F-КЛАВИШИ (как в Visual Studio)
F5              отладка: старт / продолжить     Shift+F5   остановить
Ctrl+F5         запустить без отладки           F9         breakpoint
F10 / F11       шаг через / внутрь              Shift+F11  шаг наружу

ОКНА
Ctrl+h/j/k/l    окно слева / ниже / выше / справа (работает и в REPL)
```

Клавиши `<leader>` работают и в русской раскладке: `пробел в и` = `пробел d b`.

Меню подсказок есть не только у пробела. Оно появляется после паузы на:

```text
Ctrl+w   окна            g    переходы (gd, gr ...)     z   свёртки, прокрутка
[ / ]    пред./след.     ' `  метки                    "   регистры
z=       варианты орфографии
```

Активное окно то, где подсвечена строка под курсором.

## Какие бывают окна

```text
+----------+---------------------+-------------+
| дерево   |  код                | Переменные  |
| файлов   |                     | Стек вызовов|
| <leader>e|                     | Watch       |
|          |                     | Breakpoints |
+----------+---------------------+-------------+
|           REPL | Console (вывод программы)   |
+----------------------------------------------+
  Telescope, K, <leader>ld - всплывающие окна поверх, закрываются Esc
```

Справа и снизу окна отладки, они появляются при `<leader>dc`.

## Отладка по шагам

1. Встаньте на строку и нажмите `F9` или `<leader>db`. Слева появится красная `●`.
2. `F5` или `<leader>dc`: выберите проект, откроются окна отладки.
3. `Ctrl+l` переход в «Переменные». Enter раскрывает объект.
4. `Ctrl+j` переход в стек вызовов. Enter переходит к месту в коде.
5. `<leader>de` возврат в код. Шаги: `<leader>do`, `<leader>di`, `<leader>du`.
6. `<leader>dm` включает отдельную панель режима отладки поверх левой колонки Neo-tree.
   Правая область DAP остаётся свободной для стека, переменных и другой информации.
   В панели видны цель, состояние DAP и последние события.
   `o/i/u/c/b/x/r/e` выполняют шаги, breakpoint, остановку, REPL и возврат в код. Клавиши работают и в REPL/Console.
   `Esc` выключает режим.
7. `<leader>dx` остановка. Окна остаются открытыми, чтобы был виден вывод.
   Скрыть их: `<leader>dd`.

Debug Mode пишет последние события в панель и полный журнал в
`%LOCALAPPDATA%\nvim-csharp-data\debug-mode.log`. В журнал попадают включение режима,
нажатые команды, целевое окно, фактическая позиция до/после асинхронного шага,
события DAP и ошибки. Для шагов сначала записывается `REQUEST`, а после ближайшего
`event_stopped` — `RESULT` с реальным местом остановки.

Окна пропали? `<leader>dd`. Дерево пропало? `<leader>e`.

## Если что-то не работает

```text
:LspInfo          подключён ли Roslyn
:Roslyn target    выбрать решение, если их несколько
:DotnetHealth     проверка easy-dotnet
:Lazy             состояние плагинов
:verbose nmap <leader>rr   что на самом деле назначено на клавишу
```

При первом запуске easy-dotnet может сам скачать свой сервер. Перезапустите Neovim после сообщения об этом.

Ручной запуск без `vimsharp` (Git Bash):

```bash
export PATH="$HOME/scoop/shims:$PATH"
NVIM_APPNAME=nvim-csharp nvim .
```

Обычный `nvim` без `NVIM_APPNAME` открывает AstroNvim.

## Что проверено

Headless-проверка: клавиши назначены, `Dotnet run` и `Dotnet test` существуют, окна отладки подключаются
к первому `<leader>dc`, дерево открывается, `<leader>de` возвращает в код, RU/EN переключается.
На реальном `.sln` ещё не проверены Roslyn, запуск, тесты и полный сценарий отладки.
